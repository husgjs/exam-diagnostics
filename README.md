# 试卷命题分析与学情诊断

> 不做成绩录入，不做管理系统。
> 只回答两个问题：**这道题该不该留**、**这几个人该不该盯**。

一个老师每月都会算，但算完常常没人看的那几件事：难度、区分度、临界生、偏科、知识点前置链。

零依赖、纯本地、不上传任何数据。双击启动，拖入一张成绩单，9 秒出结果。

## 它做什么

| 输入 | 输出 |
|---|---|
| 一次考试的成绩单（.xlsx） | 班级对比、学科诊断、临界生名单、偏科名单、数据质检 |
| 逐题得分（学生,题号,知识点,满分,得分） | 每题难度与区分度、讲评清单（讲哪几题、讲多久）、分层作业 |
| 多次考试 | 趋势、进退步预警、知识追踪（掌握概率）、边际收益排序 |
| 一份试卷的题干与答案 | 一节课任务单、课前前置检测、错题卷、分层卷 |

## 它不做什么（这是设计，不是没做完）

- **不做成绩录入与管理系统** —— 那是另一类工具，已有太多
- **不做学生端在线答题** —— 需要账号体系；且很多学校学生不带手机
- **不做 AI 批改手写作业** —— 手写识别与判分都会出错，判错比不判更糟
- **不做分数预测** —— 分数线年际不可比，算出来看着准、其实不能用
- **不用成绩数据评价老师** —— 复盘只谈知识点与讲法，代码里有禁语闸门

## 五条口径，每条都有依据

1. **总分 0 = 缺考，先剔除再算任何统计。**
   一个班 6 个 0 分能把均分拉低 53 分、标准差顶到年级的 1.54 倍，造出一个假的「两极分化」。
   剔除统计，但名单里保留并打「缺」字。

2. **报强弱看得分率，不看原始分。**
   五科满分不同（100/150/150/100/100），按原始分比数学永远最强、语文永远最弱——那是假的。

3. **区分度低于 0.15 的题是无效题。**
   D = 高分组得分率 − 低分组得分率，高低分组各取 27%（Kelley 1939）。

4. **补最靠前的断点，不是补最弱的点。**
   前置没通时，本点练再多次也站不住；成本要按「前置补通之后」重算。

5. **数据不足就闭嘴。**
   n<3 不出结论、锚题<2 道不做等值化、样本 12 vs 11 在报告里写明「不足以下因果结论」。

## 快速开始

```bash
# 需要 Python 3.10+，无第三方依赖（除 openpyxl）
pip install openpyxl

# Windows：双击「启动教师工作台.bat」
# 或
python teacher_app.py
```

浏览器打开 http://127.0.0.1:8765 ，把成绩单拖进去。

**示例数据**在 `示例数据/`（三次考试、40 个虚构学生、含锚题），可以直接拿来试跑。

## 还没验证的（请先看这一节）

公开这个仓库时，以下几条**没有真实数据验证**，属于已知缺口，不是遗漏：

1. **没有真实的逐题得分数据**：讲评清单、难度/区分度、个体讲评，只在 40 人虚构演示表上跑通过；真实成绩单只验证了「输出不可用」这条路径。
2. **没有真实的周作业数据**：weekly.py 的统计与周报渲染全部只经构造输入验证。
3. **没有第二次真实考试**：连续下滑、单科波动、缺考断点、重名对齐四条分支未实证。
4. **没有机构真实导出的表**：读表层四项只经四类合成表验证（25 条断言通过），真实样例到手后仍需再核。
5. **界面未全部接入**：周报与个体讲评目前是命令行，未接进工作台。

这套工具的口径是「数据不足就说不足」。上表如实反映了它自己还没吃到的数据。
